# 内容维护指南

普通更新只需要编辑 Markdown 和放入素材。每条研究或动态是一个文件夹，文字和图片、视频放在一起。中文、英文分别维护；网站版式、导航、列表和详情页由模板生成。

## 常用操作速查

| 想做的事 | 怎么做 |
| --- | --- |
| 新增一条研究、动态或资源 | 在 `src/content/posts/` 里复制 `_template` 文件夹并改名，改里面的 `zh.md`、`en.md`；图片放同一文件夹；写好后把 `draft` 改成 `false` |
| 删除一条内容 | 删掉 `src/content/posts/文件夹名`，图片和视频一起删除 |
| 暂时不公开 | 对应语言文件里写 `draft: true` |
| 新增论文 | 复制 `src/content/publications/` 里任一文件改字段；`selected: true` 标为代表工作 |
| 删除论文 | 删掉 `src/content/publications/` 里对应文件 |
| 改简介、研究方向、邮箱、学术链接 | `src/content/profiles/zh.md`、`en.md` |
| 换头像 | 替换 `src/content/profiles/photo.jpg` |
| 改履历 | `src/content/cv/zh.md`、`en.md` |
| 选择履历里的代表性论文 | 论文文件里的 `inCV: true` / `false` |
| 增加、改名、删除分类 | `src/lib/categories.ts` |
| 改完检查 | 推送到 GitHub 后自动检查；出错不会发布，原网站保持不变。也可以让 Claude 在本机先检查 |
| 发布到网站 | 用 GitHub Desktop：写一句说明 → Commit → Push，见下文“发布到 GitHub” |
| 改页面上的固定文字、导航、标志 | 见下文“页面固定文字在哪里改” |

## 修改个人概览和履历

- 中文概览：`src/content/profiles/zh.md`。
- 英文概览：`src/content/profiles/en.md`。
- 完整履历：`src/content/cv/zh.md`、`src/content/cv/en.md`。

履历页的“代表性期刊论文”由各论文文件里的 `inCV` 决定：`inCV: true` 的论文进履历，`false` 的只在学术成果页显示；没写这一行时按 `true` 处理。中英文履历用同一组论文，按年份从新到旧排列。论文的作者、期刊等信息来自论文文件，不用在履历里另写；打印或保存为 PDF 时会一起导出。论文出现的位置由履历文件里 `<!-- 论文列表 -->`（英文版 `<!-- publications -->`）这一行决定，删掉这一行则放在履历最后。

头像是 `src/content/profiles/photo.jpg`，中英文两份概览共用。换头像时直接替换这个文件，建议 4:5 竖幅、宽度 600 像素以上；`photoAlt` 是头像的文字说明。删掉两份概览里的 `photo` 一行，概览页会改回显示波浪线图。手机照片里通常带拍摄地点等信息，放进来之前最好去掉，或让 Claude 处理。

保留文档开头两行 `---` 之间的字段名，修改对应的值；第二个 `---` 之后是正文，可直接写段落、标题、列表和链接。

中文、英文可以有不同的研究重点、篇幅和顺序，不要求同步翻译。英文聚焦研究问题、具体贡献及合作方向，不加入国内项目行政信息、专利或一般荣誉。

GitHub、ResearchGate 个人地址未确定时留空或省略，模板不会显示空链接。在概览文档顶部添加 `github: https://github.com/真实账号` 或 `researchgate: https://www.researchgate.net/profile/真实个人地址` 后才显示。

## 新增一项内容

1. 在 `src/content/posts/` 里复制 `_template` 文件夹，把副本改名为这条内容的名字，例如 `finz-2026`。文件夹名是网址的一部分，只用小写英文、数字和短横线，发布后尽量不改。也可以复制任意一条现有内容来改。
2. 打开副本里的 `zh.md`、`en.md`，按里面的注释改标题、日期、分类、摘要，再写正文。只发一种语言时，删掉另一个文件。
3. 图片、视频、PDF 等放进同一个文件夹，正文用 `./文件名` 引用。
4. 模板默认是草稿（`draft: true`），不会出现在网站上。写好后改成 `false`，推送到 GitHub 即发布。

`_template` 文件夹本身始终是草稿，不会发布，留着下次复制。

下面是一个**待填写的草稿示例**，不是已发生会议的记录：

```md
---
title: "会议名称与分享主题"
date: 2026-11-13
type: news
summary: "用一两句话说明活动和分享内容。"
draft: true
pinned: false
links: []
---

填写会议、报告或活动的真实情况。

## 分享内容

可写简短说明，也可以添加图片、视频或相关链接。
```

### 顶部字段

| 字段 | 含义 |
| --- | --- |
| `title` | 标题，建议用引号包住 |
| `date` | 发布或事件日期，格式 `YYYY-MM-DD` |
| `datePrecision` | 可选：`day`（默认）、`month`、`year`，控制显示粒度 |
| `type` | 分类，目前有 `research` 研究工作、`news` 学术动态、`resource` 分享；增加、改名或删除分类见下文 |
| `summary` | 列表摘要，建议一两句话；建议和标题一样用引号包住，里面有英文冒号加空格（例如 `waves: change`）时必须加引号，否则构建会报错 |
| `draft` | `true` 不生成公开页面或列表；`false` 发布 |
| `pinned` | `true` 在概览页优先显示；“研究与动态”页不受影响 |
| `cover` | 可选封面，放在内容文件夹里，写成 `./cover.jpg` |
| `coverAlt` | 封面图的文字说明，使用 `cover` 时必须填写 |
| `coverCaption` | 可选图注，如“研究概念示意。”；真实照片和结果图按实际情况填写 |
| `coverOnPage` | 可选，默认 `true`；写 `false` 时封面只在列表里显示，详情页顶部不显示 |
| `links` | 详情页顶部的资源按钮，每项包含 `label` 和 `url`；`url` 可以是网址、以 `/` 开头的站内路径，或 `./文件名`（本文件夹里的文件）。若某个 `url` 含有 `publications` 中某篇论文的 DOI，列表和详情页会自动显示该论文的期刊名 |

分类列表在 `src/lib/categories.ts`，增加、改名、删除分类都只改这一个文件：每行一个分类，`id` 写进帖子的 `type:`，`zh`、`en` 是页面上显示的名称，顺序就是筛选栏的顺序。没有帖子的分类不显示。删除分类前先把用到它的帖子改成别的分类，否则构建会报错。

日期只知道年份时，例如填 `date: 2026-01-01` 和 `datePrecision: year`，页面仅显示“2026”；只知道月份时填该月第一天并设 `datePrecision: month`。日期里的第一天只是排序锚点，不应当作已核实的事件日。

正文不需要添加 `lang` 或 `slug`，语言由 `zh.md` / `en.md` 决定，地址由文件夹名决定。

## 正文与排版

正文没有固定栏目，可以像写公众号文章一样组织：为什么做、怎么做、看到了什么，图文穿插。研究条目建议在结尾附上论文信息和自己的角色；会议动态、分享按内容需要来写。下面这些写法可以混用，完整用法见 `src/content/posts/fixed-structure-loads/zh.md`。

一条内容的文件夹大致如下：

```text
src/content/posts/my-study/
  zh.md
  en.md
  cover.jpg
  flume.jpg
  result.png
  demo.mp4
```

图片用 `./` 引用，构建时自动压缩成 WebP。引号里是图注，可省略；方括号里是给读屏软件的文字说明：

```md
![水槽中的试验模型](./flume.jpg "水槽试验中的模型。")
```

图注里的变量和公式同正文一样用 `$...$` 书写，例如 `"波峰位于 $x/L = 0$。"`；方括号里的说明文字只能写纯文本。正文和图注中的变量都应写成公式，例如 `$H/d$`、`$\mathrm{Ur}$`，不要直接写 H/d，否则不会显示为斜体。

两三张图并排，手机上自动改为上下排列。照片会裁成同一比例；并排的是图表、不想被裁切时，用 `<div class="row fit">`：

```md
<div class="row">

![说明一](./a.jpg "图注一")
![说明二](./b.jpg "图注二")

</div>
```

比正文更宽的大图：

```md
<div class="wide">

![说明](./panorama.jpg "图注")

</div>
```

开头导语，字号稍大：

```html
<p class="lead">一两句话交代这篇在讲什么。</p>
```

提示框，适合放代码、数据或下载说明：

```md
<aside class="note">

**代码**：仓库地址和运行方法。

</aside>
```

`<div>` 和 `<aside>` 的开头、结尾两行上下各空一行，里面的 Markdown 才会生效。引用论文图时在图注里写明来源，例如“图源：Qing 等（2026），Journal of Fluids and Structures，图 1。”

## 公式

行内公式用 `$\eta = a\cos(kx-\omega t)$`，独立公式用两行 `$$` 包住：

```tex
$$
\omega^2 = gk\tanh(kh)
$$
```

公式由 KaTeX 在构建时渲染，访问者无需联网加载公式服务。

一行里并列好几个公式时，手机屏幕放不下。可以把每个公式用 `{}` 包起来，在它们之间写 `\allowbreak`。这样电脑上仍排在一行，手机上会在 `\allowbreak` 处换行：

```tex
$$
{\omega = \sigma + kU}, \qquad\allowbreak {\sigma^2 = gk\tanh kh}.
$$
```

不包 `{}` 的公式在手机上也可能在等号后面换行。

## 视频

短视频放进内容文件夹，用 `./` 引用：

```html
<video controls muted loop playsinline preload="metadata" poster="./poster.jpg">
  <source src="./demo.mp4" type="video/mp4" />
</video>
```

需要在视频下方加说明文字时，用 `<figure>` 包起来：

```html
<figure>
<video controls muted loop playsinline preload="metadata" poster="./poster.jpg">
  <source src="./demo.mp4" type="video/mp4" />
</video>
<figcaption>说明文字。</figcaption>
</figure>
```

正文里的视频滚到屏幕上时会自动静音循环播放，滚出屏幕就暂停；读者手动暂停后不会再自动播放，系统设置了“减少动态效果”时也不自动播放。因为是静音播放，视频里的讲解或声音需要读者自己打开。

GitHub 单个文件不能超过 100 MB，视频尽量压缩到几十 MB 以内。

较长视频可使用外部平台的分享链接：

```md
[观看演示视频](https://视频平台提供的真实地址)
```

也可使用平台提供的嵌入代码，但须确认平台允许嵌入；提供一个原始观看链接便于播放器无法加载时访问。中文和英文可以根据目标访客使用不同平台。

## 互动网页

已包含的线性波演示是一个浏览器教学示例，可以直接打开，也能嵌入正文：

```html
<iframe
  src="/demos/linear-wave/index.html?lang=zh"
  title="线性波互动演示"
  loading="lazy"
></iframe>

<a href="/demos/linear-wave/index.html?lang=zh">在独立页面打开演示</a>
```

英文文档使用 `?lang=en` 并改写 `title`。地址要写到 `index.html`，本地预览和正式网站才都能打开。现有演示有规则波 `linear-wave/`、不规则波 `irregular-wave/`、Stokes 波 `nonlinear-wave/`、圆柱绕射 `cylinder/`、由水线波面识别波浪力 `waterline-force/` 和运动圆柱的波浪荷载识别 `moving-cylinder/`，它们共用 `public/demos/common/` 里的计算和样式文件（运动圆柱的辐射解在 `surge-core.js`）。前四个嵌在“波浪互动实验室”（`wave-lab`）里，由水线波面识别波浪力嵌在固定结构荷载识别的帖子（`fixed-structure-loads`）里，运动圆柱嵌在浮式结构的帖子（`floating-cylinder-loads`）里。新演示放到 `public/demos/新目录/`，正文引用其入口。互动页面开发一次后，即可当作资源反复引用。

嵌入正文时，演示框高度会自动贴合内容，演示自带的中英文切换会隐藏。单独打开时，左上角有返回帖子的链接；这个链接写在演示页里（`data-back` 链接的 `href` 和 `setupPage` 的第二个参数），演示换到别的帖子或帖子改名时要一起改。演示放在 `public/demos/`，不在帖子文件夹里，删除帖子不会删除演示。

JavaScript 绘图、切换工况、浏览器计算和预先计算数据播放可直接运行。需要远程 Python / MATLAB / OpenFOAM 计算的功能需另接服务，不在 GitHub Pages 内启动。

## 论文、代码和其他资源链接

在条目顶部增加资源按钮，例如：

```yaml
links:
  - label: "论文"
    url: "https://doi.org/真实DOI"
  - label: "代码"
    url: "https://github.com/本人账号/仓库"
  - label: "互动演示"
    url: "/demos/linear-wave/index.html?lang=zh"
  - label: "报告幻灯片"
    url: "./slides.pdf"
```

上述 DOI 和账号都是写法占位，填写真实可访问地址后再发布。没有开源代码或视频就省略对应按钮，不显示尚不存在的资源。

论文列表的数据保存在 `src/content/publications/*.md`。新增论文时复制一个现有文件，按其字段更新作者、题目、期刊、年份和 DOI / 期刊链接；同一事实不必分别在中英文复制一份。`authors` 为作者列表，`url` 为论文链接，`selected: true` 标为代表论文；中文可选评价字段为 `jcr` 和 `impactFactor`，英文页不显示这两项。论文按年份从新到旧排列，同一年内按文件名倒序；文件名以年份开头，例如 `2026-floating-cylinder.md`。作者名写成 `Qing J` 或 `Jingbo Qing` 会自动加粗。共同第一作者写在 `equalContribution` 中，例如 `equalContribution: ["Liu J","Qing J"]`，名字要与 `authors` 里完全一致，页面会在这些名字后加 † 并注明“共同第一作者”。`inCV: true` 表示放进履历的“代表性期刊论文”，`false` 表示只在学术成果页显示。

研究详情可以关联论文，但它还应回答“研究了什么、本人做了什么、有什么结果”，避免仅重复论文题目。贡献陈述应以本人确认的实际工作为准。

## 隐藏、删除和单语发布

- 暂时隐藏：将对应语言文档设为 `draft: true`，重新构建发布。两种语言都设为草稿时，文件夹里的图片和视频也不会发布到网站。
- 删除某种语言：删除该语言文档，另一种语言仍可保留。
- 删除整项内容：删除该条目文件夹，素材随之删除。已发布过的地址会失效，若有长期外部引用，优先保留说明页或另设跳转。
- 两种语言都存在才展示对应详情的语言切换；不生成空白译文。

公开 GitHub 仓库中的草稿原文和历史版本仍可查看。`draft` 是网页发布控制，不是保密功能；未准备公开的内容保存在仓库外。

## 首页显示和分享预览

- 概览页的“研究与动态”最多显示 5 条：`pinned: true` 的排在前面并标“精选”，其次是研究工作，其余按日期从新到旧；全部内容在“研究与动态”页，那里先按分类（顺序同 `src/lib/categories.ts`，即研究工作、学术动态、分享）、再按日期从新到旧排列。
- 链接转发到微信、LinkedIn 等平台时显示的预览图是自动生成的：研究帖子用自己的封面，其他页面用头像。SVG 封面不能做预览图，会自动改用头像。

- **期刊分区和影响因子**：`impactFactor` 取论文发表当年的 JCR 数据，页面底部有一句统一说明，不必逐条注明。当年数据尚未公布时先填最新一年的；每年 6 月前后新的 JCR 发布后，把上一年发表论文的数值改成当年数据（例如 2027 年发布 2026 年数据后，改 2026 年发表的论文）。`jcr` 分区随之核对。
- **新论文**：发表后加一份论文文件；有对应帖子时，在帖子的 `links` 里放论文的 DOI 链接，期刊名会自动显示。
- **会议、获奖、项目**：写进履历文件。

## 发布到 GitHub（不用命令行）

用免费的 GitHub Desktop 图形界面即可。

第一次：

1. 安装并登录 GitHub Desktop，用 **File → Add Local Repository** 选中 `academic-homepage` 文件夹。
2. 第一次发布前，先让 Claude 检查一遍会公开的文件和历史记录。
3. 点 **Publish repository**，取消勾选 **Keep this code private**（免费版 GitHub Pages 需要公开仓库），然后发布。
4. 在 GitHub 网页上按 [GitHub Pages 部署](GitHub-Pages部署.md) 打开 Pages。

以后每次更新：

1. 改好文件后打开 GitHub Desktop，左侧会列出改动过的文件。
2. 在左下角写一句说明，例如“新增 FiNZ 2026 动态”，点 **Commit to main**。
3. 点右上角 **Push origin**。几分钟后网站更新。

网站没有更新时，到 GitHub 仓库的 **Actions** 页面看失败原因，或者把截图发给 Claude。

## 其他事项（需要时交给 Claude）

- **工具升级**：Astro 等工具偶尔需要升级，平时不用管；需要时让 Claude 升级并检查。
- **搜索引擎收录**：可以在 Google Search Console、百度搜索资源平台提交网站地图 `sitemap.xml`，加快被搜到。
- **自有域名、国内访问速度**：见 [GitHub Pages 部署](GitHub-Pages部署.md)。
- **隐私**：手机照片里通常带拍摄地点，放进网站前要去掉；仓库是公开的，不想公开的资料放在仓库外。项目根目录的 `个人主页架构.md`、`网页构想.md` 已加入忽略列表，只留在本机。

## 检查和发布

改好的内容推送到 GitHub 后，网站会自动构建、检查并发布，一般几分钟内生效。如果有错误，比如图片文件名写错、必填字段漏了，这次不会发布，原来的网站保持不变；在 GitHub 仓库的 Actions 页面可以看到是哪个文件、哪个字段出了问题。

想在推送前先看看效果或检查一遍，可以让 Claude 在本机运行预览和检查。检查时还会列出几类提示：哪些内容还是草稿、文件夹里哪些文件没有被用到（可以删掉）、哪些文件太大（超过 10 MB 建议压缩，超过 100 MB 无法上传到 GitHub）。

会用命令行时，对应的命令是 `npm run dev`（边写边看）和 `npm run verify`（全面检查）。首次设置 GitHub 发布见 [GitHub Pages 部署](GitHub-Pages部署.md)。

正文中的 `./` 素材路径和 `/demos/` 等站内路径会在构建时适配 GitHub Pages 项目子路径，不要给素材地址硬编码 `/academic-homepage`。
